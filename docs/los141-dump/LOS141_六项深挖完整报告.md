# LOS14.1 六项深挖（含重大纠错）

## ★★ 最重要的纠错：之前的"45条/52条"都是错的

我之前用"遇到第一个 ret 就 break"反汇编，把函数**中途的提前返回分支**当成了函数结尾。
正确做法：按**符号边界**反汇编完整范围，所有返回汇聚到唯一的 ret。

- primary_display_resume：真实 **457 条**（0x4a2e54-0x4a3578），唯一 ret @0x4a2f04
- primary_display_trigger：真实 **365 条**（0x4a4a00-0x4a4fb4），唯一 ret @0x4a4acc

## 3. _cmdq_start_trigger_loop 的调用者（谁在 resume 里调它）

在 primary_display_resume 里 **2 处**：
- **0x4a2ff8**（power_on 之后、path_connect 之前）
- **0x4a3428**（path_start 之后、path_trigger 之前）

之前以为是 MMProfile 调用——实际是 resume 的 cmdq loop 启动步骤。

## 4. cmdqCoreSetEvent(0x50) 的 0x50 是什么

0x50 = 80，是 **CMDQ 硬件事件号**（cmdq event enum）。
内核 rodata 有 259 个 `CMDQ_EVENT_*` 字符串（@0xc79e50 起），但表是**逆序排列**，
字符串序号 ≠ 枚举值，无法静态精确映射出名字。
从上下文（trigger loop 里、检查 session mode 后调用）看，是 DSI/帧同步相关事件。
0x192/0x193/0x194 是错误事件（配合 dprec_event_op(0xff02) 上报）。

## 5. primary_display_trigger 完整逻辑（365 条，ret @0x4a4acc）

```
4a4a24 bl bc_set_next
4a4a2c ldr w1,[x20,#0x3d0]; add w1,#1; str 回   ; 递增计数器
4a4a44 bl primary_path_lock
4a4a48 ldr w0,[x20,#0x1e0]; cbz → 分支        ; CMDQ loop 标志
4a4a54 ldr w0,[x0,#0x28]; cmp #0xf1            ; path 状态
4a4a60 cbnz w22 → 分支
4a4a80 ldr w0,[x20,#0x44]                      ; ★ session mode
4a4a84 cmp #1 → 0x4a4c5c
4a4a8c cmp #3 → 0x4a4d6c
4a4a94 cmp #2 → 0x4a4d18
4a4a9c cmp #4 → 0x4a4b34
4a4ab0 bl dprec_logger_done; 4a4ab4 path_unlock
4a4acc ret
```
**核心：按 session mode([+0x44]) 1/3/2/4 分派四种触发路径**。

## 6. pgc+0x44 是什么字段 —— **session mode（DISP_SESSION 枚举）**

5 处写入：
| 地址 | 值 | 上下文 |
|---|---|---|
| 0x4a2c38 | 2 | resume 内 |
| 0x4a2dcc | 1 | resume 内 |
| 0x4a3b54 | w20(参数) | switch_mode |
| 0x4a3cd0 | 1 | switch_mode |
| 0x4a3e1c | 1 | switch_mode |

trigger 里 `cmp [+0x44],#1/2/3/4` 四路分派 → 这是 `enum DISP_SESSION_TYPE`
（1=DIRECT_LINK, 2=VIDEO, 3=MEM_OUT 等）。MTK display 标准字段 `pgc->session_mode`。

## 纠错链总结（本轮推翻的旧结论）

| 旧结论 | 正确结论 |
|---|---|
| resume 是 45 条薄 wrapper | **457 条**，含 power_on/loop/path_config/lcm_resume/path_trigger 全链路 |
| resume 不触发一次 | resume 内 **0x4a34c0 调 dpmgr_path_trigger** |
