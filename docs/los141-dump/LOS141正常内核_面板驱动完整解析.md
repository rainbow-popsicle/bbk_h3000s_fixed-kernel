## 1. 表（核心发现：根据硬件 ID 二选一）

硬件 ID 来源：辅助函数 `0x458608` 从 **cmdline 的 `lcm_vendor_id=`** 读一个字符，
减去 0x30 得 ID；找不到则 ID=0。

- **ID==1 → 291 项表** @0xffffffc000f097b0（首项 `B0 05`，尾 `11 / FC120 / 29 / FC40 / FD`）
- **ID==0 → 23 项表** @0xffffffc000f0e988（首项 `FF AA55A5 80`，即 BOE 表，和我们 stock_tables.c 表A 一样）
- 其他 ID → 打印 `failed to get lcm id`，推 23 项表兜底

本 boot.img 的 cmdline `bootopt=64S3,32N2,64N2 androidboot.selinux=permissive buildvariant=userdebug`
**没有 `lcm_vendor_id=`** → ID=0 → **用 23 项 BOE 表**。

睡眠表（suspend）：4 项 @0xffffffc000f09690 = `28 / 10 / FC120 / FD`

表项格式：**每项 0x48 字节**（cmd@+0, count@+4, para@+5），0xFC=DELAY(ms)，0xFD=END。

## 2. timing（get_params，也是二选一）

公共：`width=1536 height=2048`、`lcm_if=3(DSI_DUAL)`、`mode=3(BURST_VDO)`、
`lane=4`、`packet_size=256`、`ssc_disable=1`。

- **ID==0（本机能亮的那套）**：`v_sync=2 v_bp=40(0x28) v_fp=40(0x28) v_act=2048`、
  `h_sync=4 h_bp=200(0xc8) h_fp=200(0xc8)`、`ssc_range=500(0x1f4)`、`dsc_enable=1`
- **ID!=0,!=1 的另一分支**：`v_sync=12(0xc) v_bp=40 v_fp=20(0x14) v_act=2048`、
  `h_sync=24(0x18) h_bp=80(0x50) h_fp=80(0x50)`、`ssc_range=425(0x1a9)`

## 3. 上电顺序（resume @0x458420）

三个 GPIO 全局变量：`[x19+0xe0]`、`[x19+0xe4]`、`[x19+0xe8]`（x19=0xffffffc00122f740），
由 `lcm_get_gpio_infor`（set_util_funcs 里 bl 0x306c00）从 DTB 运行时填充。
DTB 的 lcm 节点属性：`gpio_lcd_rst` / `gpio_lcd_enp` / `gpio_lcd_enn` / `gpio_lcd_id`。
helper `0x4581bc` = `mt_set_gpio_mode + mt_set_gpio_dir + mt_set_gpio_out(gpio, val!=0)`。

```
1. GPIO[e4] = 1        ; delay 2ms      ← 供电轨之一
2. GPIO[e8] = 1        ; delay 15ms(0xf) ← 供电轨之二
3. GPIO[e0] = 1        ; delay 5ms      ← RST 拉高
4. GPIO[e0] = 0        ; delay 2ms      ← RST 拉低
5. GPIO[e0] = 1        ; delay 15ms(0xf) ← RST 再拉高
6. 调用 init(0x458344) ← 关键：resume 里调 init，init 内部再推表
```

顺序本质：**先两路供电(enp/enn) → 再 RST 复位脉冲 → 推表**，且 RST 之后**调用 init 二次初始化**。

## 4. 脉冲（reset 脉冲宽度）

- RST = `[e0]`：`高5ms → 低2ms → 高15ms`（**第三段 15ms，不是我们的 25ms**）
- 两路供电：enp 拉高后等 2ms，enn 拉高后等 15ms
- **resume 末尾调用 init**：init 里根据硬件 ID 再推一次表（ID=0 时推 23 项表）
- compare_id (0x45803c) 里另有 RST 脉冲 + mdelay(2/5/10)，用于读 ID 前的复位

## 5. rst_new（是否有第二复位脚）

- LCM_DRIVER 结构里没有任何 RST_NEW 成员；resume/suspend 只操作 e0/e4/e8 三个 GPIO
- DTB 的 `/soc/lcm` 只有 `gpio_lcd_id = <&pio 89 0>` 和 `reg-lcm-1v8-supply`，**没有 rst_en_new**
- 结论：**这颗正常内核没有 RST_NEW 概念**，只用单一 RST（e0）

## 与我们内核的关键差异（重点）

| 项 | 正常内核 (LOS14.1) | 我们的内核 |
|---|---|---|
| 表选择 | cmdline `lcm_vendor_id` 二选一（291 项 / 23 项） | 固定 23 项，无硬件 ID 判断 |
| timing | ID=0: v_bp40/v_fp40/h_sync4/h_bp200/h_fp200（**分支B**） | 曾被改成 40/40/4/200/200，但**通过改源码常量**（无硬件 ID 判断） |
| 上电顺序 | e4↑2ms → e8↑15ms → e0↑5ms → e0↓2ms → e0↑15ms | RST 先，VSP/VSN 后（顺序不同！） |
| reset 脉冲 | 高5 / 低2 / 高15 | 5/2/25（第3段 25ms ≠ 15ms） |
| resume 调 init | **是**（resume 末尾调 init 二次推表） | 否（resume 只推一次表） |
| rst_new | 无 | 有 GPIO_LCD_RST_EN_NEW（实测和主 RST 同为 1016，无效） |

**最可能的三个根因差异**：
1. **上电顺序相反**：正常内核先供电（e4/e8）再复位（e0脉冲）；我们是先复位再供电
2. **resume 调用 init**：正常内核 resume 里会调 init 再次推表，我们不会
3. **脉冲第三段 15ms vs 25ms**
