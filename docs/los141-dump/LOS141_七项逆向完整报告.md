# LOS14.1 七项逆向完整报告

内核：LOS14.1 (3.18.35, 2021, 功能全好)
定位：原厂符号索引 +7 = LOS 索引（多锚点校准）+ 机器码指纹

## 1. primary_display_suspend 停不停 trigger loop？——**不停**

`primary_display_suspend @0x4a8e0c`（56 条，ret @0x4a8ee8）：
```
4a8e50 add x0,x19,#0x9e8; ldr w0,[x0,#0x1e0]; cbz → 跳过
4a8e64 bl 0x4aac7c    ; disp_sw_mutex_lock
4a8e70 bl 0x49e048    ; primary_path_lock
4a8e80 ldr w0,[x21,#0x28]; cmp #0xf1   ; 状态检查
4a8eb8 bl 0x4aaca8    ; disp_sw_mutex_unlock
4a8ebc str wzr,[x19,#0x3d0]            ; 清 0x3d0（不是 0x1e0）
4a8ed4 bl MMProfileEnableEvent
```
**没有调用 `_cmdq_stop_trigger_loop`(0x49e0b4)**。它检查 0x1e0 只是为了 mutex 保护，
清的是 `[+0x3d0]`（另一个字段），**不停 CMDQ trigger loop**。

## 2. dpmgr_path_start 之后有没有"触发一次"？——**没有**

`dpmgr_path_start @0x491330`，主体到 **ret @0x491400**（0x491494 起是下一个函数）：
```
49135c bl 取模块列表; 491368 bl 取模块数 → w22
4913a0 循环 w22 个模块:
   ldr x0,[x0,#0x20]     ; 模块 start 回调
   blr x2 @0x4913d8      ; ★ 逐个调 start 回调
491400 ret
```
只遍历模块调 `[obj+0x20]`（start 回调），**没有调 trigger**（不触发一次）。

## 3. cmdqRecStartLoop 内部有没有设初始事件？——**没有**

`cmdqRecStartLoop @0x42faf4`：
```
cbz x0 → ret (NULL handle)
bl printk("...") @0x42fb14
bl 0x433ff4        (check)
bl 0x44b23c        (★ 核心 start loop)
bl printk(...) @0x42fb44
ret
```
只是包装，没有设初始事件。下层 `cmdq_task_start_loop @0x42f038` 写 CMDQ 寄存器：
`bl 0x42df28` 两次（w1=2, 然后 w1=8/orr w2,w20,#1）——这是配置 loop 属性，非"初始事件"。

## 4. [global+0x1e0] 是什么标志？——**CMDQ trigger loop 使能标志**

全局基址 `0x1265000+0x9e8 = 0x12659e8`，标志在 `+0x1e0`（地址 0x1265bc8）。
证据：
- `_cmdq_start_trigger_loop`@0x4a1224：检查 `[+0x1e0]` 非0 才启动，内部调 `disp_lcm_is_video_mode`(0x4aaa60)
- `_cmdq_stop_trigger_loop`@0x49e0b4：同样检查 `[+0x1e0]`，调 `cmdqRecStopLoop`(0x42fa58)
- `primary_display_suspend`/`resume` 都检查它做 mutex 保护
→ 这是 primary_display 结构里的 **CMDQ trigger loop 使能/状态标志**（MTK 源码里常叫 cmdq_triggle_en）。

## 5. DSI_DumpRegisters 触发入口

`DSI_DumpRegisters @0x46ed90`，4 个直接 bl 调用者：
| 调用点 | 所在函数 |
|---|---|
| 0x46f648 | **Dsi_Config_VDO_Timing** @0x46f470（配时序时自动 dump） |
| 0x478974 | DSI_set_cmdq_V2_Wrapper_DSIDual @0x477e54 |
| 0x47bf54/74 | TPanelMaster_get_dsi_timing @0x47bf38（= ddp_dsi_dump） |

函数签名：`DSI_DumpRegisters(module, flag)`——`tbnz w1,#0x1f` 检查 flag bit31，
`cmp w0,#0x20/#0x12/#0x13` 按模块类型分支。

## 6. disp_lcm_resume @0x4aa668 及其调用者

```asm
4aa668 stp...
4aa68c bl printk("...")
4aa690 cbz x19 → 返回
4aa694 ldr x0,[x19]          ; plcm
4aa69c ldr x19,[x19,#8]      ; plcm->driver
4aa6a4 ldr x19,[x19,#0x28]   ; driver->resume 函数指针
4aa6ac blr x19               ; ★ 调用真正的 lcm_resume
4aa6bc ret
```
薄 wrapper，最终 `blr` 到 `lcm_resume`(@0x458420)。
调用者 2 处：`bl @0x4a15a0`（primary_display_mem_out_trigger 内）和 `bl @0x4a326c`（primary_display 模块内）。

## 7. ddp_dsi_trigger 里的 [global+0x7a8]

`ddp_dsi_trigger @0x479b60`:
```
479b60 adrp x2, 0x1231000
479b6c ldr w2,[x2,#0x7a8]     ; 全局 0x12317a8
479b7c cbnz w2, 479b9c        ; ★ 非0 → 跳过魔数包
479b80 mov w5,#0x3909; movk #0x2c,lsl16  ; 魔数 0x002c3909
479b98 bl DSI_set_cmdq(魔数)
479ba4 bl DSI_Start
```
全内核只有 1 处 `str [x?,#0x7a8]`（@0x5b7010，不同全局基址，不是同一个变量），
说明 `0x12317a8` 是 `_dsi_context` 全局区里只被初始化（memset/结构体赋值）的字段。
语义：**PanelMaster/TV 模式状态标志**——非0（PanelMaster 激活）时不发魔数包，直接 DSI_Start。
（MTK PanelMaster 是工厂/外接显示功能，激活时走不同触发路径。）

## 关键新发现汇总（对黑屏调查）

1. **suspend 不停 CMDQ loop**——唤醒时 loop 本来就在，不需要重启
2. **path_start 不触发一次**——唤醒后第一帧靠正常 trigger 流程
3. **LOS 自带 DSI_DumpRegisters**，配时序时自动 dump——不需要注入调试代码
4. **disp_lcm_resume → blr driver->resume(@0x458420)** ——这是面板 resume 的完整路径
5. **trigger 有 PanelMaster 旁路**——如果状态非0会跳过魔数包（我们内核没有这个考虑）
