## 一、可以立即使用的成果

### 1. 内核编译流水线（已完全打通，可复用）

- 仓库（你的 fork）：`bbk_h3000s_fixed-kernel`，源码 `Haoduo9/android_kernel_bbk_h3000s` 分支 `lineage-15.1-h3000s`
- 构建入口：`.github/workflows/build-kernel.yml` → 手动触发，一次约 7 分钟
- 关键脚本：
  - `scripts/build.sh`（v27）— 拉源码、配工具链、打补丁、编内核、打包 boot.img
  - `scripts/bootimg.py` — boot.img 解析/拆包/重组（156 项自测）
  - `scripts/patch_ramdisk.py` — 改 ramdisk 属性（如 `ro.adb.secure=0` 免授权）
  - `scripts/patch_binder.py` — 给 binder 驱动补 hwbinder/vndbinder
  - `tests/test_lcm_patch.py` — 在 mock 树里用真 bash 验证屏驱动补丁
- 产物：`s3pro-kernel-XX.zip`（含 boot.img、build.log、build-info.txt）

### 2. 已确定修复的内核问题

| 问题 | 现象 | 修法（已写进 build.sh） |
|---|---|---|
| 屏驱动找不到 GPIO 节点 | `lcm handle is null` + `invalid GPIO -2` + `lcm_get_gpio_infor` 栈 | 把 `of_find_compatible_node` 的 compatible 从 `mediatek,mt8173-lcm` 改成设备树里真实存在的 `mediatek,nt35523_fhd`；属性名 `gpio_lcm_*` 映射到 `gpio_lcd_enp/enn/rst`；去掉 `goto out` 和 `out:` 标签（避免 -Werror） |
| 缺 `/dev/hwbinder`、`/dev/vndbinder` | `hwservicemanager: Failed to aquire binder FD` 所有 HAL 起不来 | 树的 binder 是 MTK 魔改版，只有 `misc_register(&binder_miscdev)`；`patch_binder.py` 追加 hwbinder/vndbinder 两个 miscdevice 并注册 |
| DTB 版本不匹配 | 内核起不来被看门狗复位 | build.sh 自动检测树内 DTS，改用 `Image.gz-dtb` 目标（自带 DTB），不再外挂成品内核里拆出的老 DTB |
| adb 无法授权（屏黑点不了弹窗） | `unauthorized` | `patch_ramdisk.py` 把 `ro.adb.secure` 改 0 |

打完这些补丁的内核（run32）实测：**系统能启动到 Android、adb 可用、HAL 正常、稳定运行 256 秒不复位**。

### 3. 已确定修复的系统层问题

- **缺 `libdrm.so`** → 从 `lineage-14.1-...-h3000s.zip` 里提取 `system/lib64/libdrm.so`(67,608) 和 `system/lib/libdrm.so`(50,708)，推进 `/system/lib64/`、`/system/lib/`、`/system/vendor/lib64/`、`/system/vendor/lib/`
- 效果：`libEGL: dlopen failed: library "libdrm.so" not found` 消失，三个 EGL 驱动全部 `loaded`

## 二、当前卡点：GPU 用户层代差（未解决）

### 现象

```
init.svc.surfaceflinger   = restarting      （每 5 秒崩一次，无限重试）
#00 pc 0000000000000000                      ← 跳空指针
#01 /system/vendor/lib64/libpvrANDROID_WSEGL.so
#02 /system/vendor/lib64/libIMGegl.so (IMGeglInitialize+176)
#03 /system/lib64/libEGL.so (egl_display_t::initialize)
```

### 已排除的原因（都有证据）

| 怀疑点 | 验证结果 |
|---|---|
| `/dev/pvrsrvkm` 不存在 | 误判。`libsrv_um.so` 里只有 `/dev/dri`、`/dev/pvr_sync`、`/dev/sw_sync`，没有 pvrsrvkm |
| 内核 GPU 驱动没起来 | 内核正常：`[drm] Initialized pvr 1.7.4167538 on minor 0`，`/dev/dri/card0` 存在 |
| GPU 库文件被换错版本 | `libIMGegl.so`(239,536)、`libsrv_um.so`(1,987,832)、`libpvrANDROID_WSEGL.so`(67,544)、`gralloc.default.so`(15,912) 与**原厂 7.0 逐字节相同** |
| `/vendor` 没挂对 | `/vendor -> /system/vendor` 符号链接正常 |
| 内核缺 hwbinder | 已修（run32 内核里 hwbinder/vndbinder 各 2 处） |

### 结论

**内核 GPU 驱动走 DRM 接口**（cappu 源码树，PVR 1.7.4167538），**用户层 GPU 库是原厂 7.0 那一代**。两者运行时握手失败，`PVRSRVConnect` 拿不到函数表 → WSEGL 空指针 → SurfaceFlinger 崩 → 无画面。

### 唯一可能的打通路径

**换一套配 cappu 内核的 Android 8.1 GPU 用户层库**，来源优先级：

1. `Haoduo9/android_vendor_bbk_h3000s`（已下载，见 `work/hvendor/`）——里面确实有设备上缺的 `gralloc.mt8173.img.so`(90,496) 和 `hwcomposer.mt8173.so`(248,184)，但**单独推这两个文件没有解决问题**（2026-11-08 实测）
2. Mi Pad 3（cappu）的 LineageOS 15.1 vendor 库——需要完整 ROM
3. 步步高原厂 7.0 内核源码（拿不到；该内核的 PVR 集成会创建 `/dev/pvrsrvkm`，与用户层配套）

### 注意：整包覆盖 vendor 会砖

2026-11-08 曾把 `android_vendor_bbk_h3000s` 的 406 个文件整包推进 `/system/vendor`，结果设备卡 LK logo、adb 全无（关键 HAL/critical service 崩溃循环）。
差异统计：66 个新增、8 个大小不同、332 个同名同大小。
**恢复方法：用 SP Flash Tool 只刷 `system_h3000s_los15.1\system.img`**（已验证可行）。

## 六、经验记录（避免重复踩坑）

- 这棵树的 `CONFIG_ANDROID_BINDER_DEVICES` 在 Kconfig 里**不存在**，defconfig 里写了也没用，`olddefconfig` 会丢掉
- 树的 binder 是 MTK 魔改版，只有 `/dev/binder`
- 屏驱动 `of_find_compatible_node` 用的 compatible 在 DTB 里不存在（原厂/FIXED5/作者 DTB 三份都没有）
- Windows 下解压内核树/镜像超过 260 字符路径会丢文件，要解到短路径
- `adb root` 在这台机被系统设置禁用（"root access is disabled by system setting"）
- 抓 logcat 时设备只有约 15-20 秒窗口（修好 binder 后变长）
